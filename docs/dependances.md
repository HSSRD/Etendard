# Dépendances et configuration

Pourquoi chaque dépendance directe de `package.json` et chaque fichier de configuration à la racine existent.
Vérifié le 2026-11-20 (#83), Expo SDK 58. Versions, classement et règle des pairs : ADR 0013 ; `scripts/dependances.test.ts`
vérifie que la liste ci-dessous suit `package.json`.

Preuves citées :

- **import** : `pnpm exec knip --trace-dependency <nom>` ;
- **pair** : `peerDependencies` non optionnelles du paquet cité, lues dans `node_modules` ;
- **SDK** : `node_modules/expo/bundledNativeModules.json` (versions fixées par Expo SDK 58) ;
- **doctor** : `pnpm dlx expo-doctor` (20/20 avec les dépendances actuelles) ;
- **retrait** : `pnpm remove`, puis `pnpm build`, `pnpm check` ou `expo-doctor` ;
- **bundle** : sources des bundles iOS et Android, lues dans les sourcemaps de `pnpm build:natif --source-maps --no-bytecode`.

Essai de retrait commun à six paquets (`@expo/metro-runtime`, `expo-constants`, `expo-linking`, `expo-system-ui`,
`react-dom`, `react-native-screens`) : le build web passe toujours, mais pnpm réinstalle les cinq pairs obligatoires
(`auto-install-peers`), hors du contrôle de `expo install` et du groupe « Expo SDK » de Renovate. Seul
`expo-system-ui` disparaît vraiment. `expo-doctor` signale alors trois pairs manquants (`expo-constants`, `expo-linking`,
`react-dom`) : « Native module peer dependencies must be installed directly ». D’où la règle des pairs d’ADR 0013 : un pair obligatoire que le SDK versionne est déclaré.

Pairs obligatoires non déclarés, hors de cette règle : `vite` (pair de `vitest` ; pnpm le choisit seul et Renovate ne le suit pas : il ne change que si `vitest` exige une version plus récente), `playwright-core` (pair d’`@axe-core/playwright`,
même version que `@playwright/test`, qui l’apporte par `playwright`) et `@expo/log-box` (pair d’`expo-router` et d’`@expo/metro-runtime`, dépendance d’`expo`).
Aucun n’est dans `bundledNativeModules.json`. `playwright-core` et `@expo/log-box` suivent le paquet qui les apporte.

## Modules natifs exclus de l’autolinking

`expo.autolinking.exclude` de `package.json` retire de l’autolinking (iOS et Android) ces modules natifs qu’aucun
`package.json` du repo ne déclare : pnpm les installe comme pairs (`auto-install-peers`), et
`expo-modules-autolinking react-native-config` les liait dans les apps, hors des versions du SDK (#89). Aucune source de
ces paquets n’est dans les bundles iOS et Android (**bundle**) : un module lié mais jamais appelé alourdit les apps.
`pnpm build:natif` ne verrait pas un appel ajouté plus tard : le code qui en importe un le déclare avec
`pnpm expo install` et le retire de la liste (`scripts/dependances.test.ts` refuse un module déclaré et exclu).

| Module                         | Pourquoi pnpm l’installe                                                                                                                                                |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `react-native-gesture-handler` | pair de `react-native-drawer-layout`, dépendance d’`expo-router` (navigateur Drawer, absent du bundle)                                                                  |
| `react-native-reanimated`      | pair de `react-native-drawer-layout`, dépendance d’`expo-router` (navigateur Drawer, absent du bundle)                                                                  |
| `react-native-worklets`        | pair de `react-native-reanimated` ; pair optionnel d’`expo-modules-core`, dont l’intégration native est facultative (Android : `findProject(":react-native-worklets")`) |
